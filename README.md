# Folio · 简历建站

> 把零散经历，变成可以直接分享的个人简历网站。

Folio 是一个全栈 Web 应用。你只需粘贴旧简历、项目笔记和目标岗位 JD，Folio 会先整理出一份事实准确的简历资料，再生成 2–3 套版式明显不同的个人网站。选定样式后，可以通过对话继续修改，最后下载单文件 HTML，或发布为公开链接。

---

## 产品特点

- **只写你真的做过的事**：只使用你提供的事实，区分「你的经历」与「岗位要求」，合并重复材料，并按目标岗位安排栏目顺序。团队成果会注明归属，不写成个人独立完成。
- **一份资料，多套样式**：默认生成 3 套候选，分别是「极简单栏」「双栏侧栏」「项目卡片」。内容事实一致，布局、信息层级和视觉风格各不相同，都适配手机。
- **自定义样式**：用一句话描述想要的风格（如“暗夜科技风”“日系杂志留白”），即可生成新样式，并和内置样式一起在「样式方案」中切换。
- **对话编辑**：可以改写经历、新增或移动栏目、切换单栏与双栏、调整字体和间距。更换主题色时，背景、卡片、文字、链接和按钮会协调调整，也可以单独修改某个区块的颜色。
- **源码可控**：「预览 / 代码」一键切换，代码面板支持 HTML/CSS 语法高亮、格式化和应用代码。手动修改后，后续对话以你的源码为准。
- **版本历史**：选用样式、应用修改、更换头像时都会自动保存版本。恢复旧版本时，会把它复制为当前的新版本，不会覆盖历史。
- **下载与发布**：导出的 `.html` 内嵌样式和头像，可以单独打开；发布后生成 `/page/{随机ID}` 链接，访客无需登录即可查看。重新发布会沿用同一个链接。
- **自带模型**：每个账号在「模型设置」中填写自己的 OpenAI 兼容服务。Token 由服务端加密保存，不同账号的配置互不共享。未配置模型时，也能用内置规则体验完整流程。
- **账号与数据**：支持邮箱注册、登录、找回密码和 Google 登录。简历、候选样式、对话、版本、头像和发布记录都保存在云端，换设备登录后可以继续编辑。

## 快速上手

### 1. 先看看示例
打开首页，点击左侧或顶部的「示例」，无需登录即可浏览同一份材料生成的 3 套网站，并在桌面和手机视图之间切换。

### 2. 粘贴材料并生成
1. 在首页大输入框中粘贴旧简历、项目笔记或目标岗位 JD，也可以点「导入 TXT / Markdown」或「从示例开始」。
2. 选择生成「2 套」或「3 套」，点击右侧蓝色圆形按钮。
3. 首次使用需要登录或注册，登录后会自动开始生成。

> 小提示：经历按「公司 | 职位 | 2021.07 - 至今」加「- 要点」的格式书写，识别效果最好。在 JD 前加上「目标岗位 JD」标题，Folio 就会把它当作岗位要求，而不是你的经历。

### 3. 挑选样式
- 在工作台右侧的「样式方案」中，点击卡片查看完整页面，满意后点「使用此样式」。
- 想要别的风格？在卡片栏最后的「生成新样式」中描述风格即可。
- 资料不全时，左侧对话会提出最多 3 个关键问题，补充后效果更好。

### 4. 继续编辑
在左侧对话框直接说出你的要求，例如：
- 「换成雾霾蓝主题，页脚背景单独设为 #1E293B」
- 「新增荣誉获奖栏目，放到项目经历后面」
- 「调整为双栏布局，间距宽松一些」
- 「把第一段工作经历改得更突出性能优化成果」（需要先配置模型）

也可以使用顶部入口：
- **编辑资料**：用表单直接修改姓名、联系方式、经历和栏目。
- **代码**：在预览区切换到「代码」，手动修改 HTML 后点「应用代码」。
- **头像**：点击预览中的头像即可上传或更换。

### 5. 下载或发布
- **下载**：在预览工具栏或代码面板中点「下载 HTML」。
- **发布**：点击右上角「发布」生成分享链接，可以一键复制。之后修改了内容，再点「用当前版本更新发布页」即可，链接保持不变。
- 发布者登录后打开自己的发布页，可以直接在页面上更换头像。

### 6. 配置自己的大模型（可选）
在首页顶部、「我的简历」或工作台中打开「模型设置」：
1. 填写 API Base URL（如 `https://api.openai.com/v1`）和 API Token。
2. 点「获取模型」选择模型，或手动填写模型 ID。
3. 先「测试连接」，再「保存设置」。

配置完成后，资料梳理、对话改写和自定义样式都会改用你的模型。

## 部署

### 方式一：在 Atoms 平台发布（推荐）
项目基于 Atoms Cloud 构建，数据库、登录（含 Google）和头像存储都已自动配置好。

1. 在 Atoms 中打开项目，确认 Preview 运行正常。
2. 点击 Preview 上方的 **Publish**，按需修改链接后再次点击发布即可。
3. 发布后，请在生产地址上验证一遍邮箱登录和 Google 登录。

之后应用更新时，已发布的 `/page/{ID}` 链接和头像会继续有效，因为发布快照和头像都持久保存在数据库与对象存储中。

### 方式二：自行部署
项目结构：

```
app/
├── frontend/   # Vite + React + Tailwind + shadcn/ui
└── backend/    # FastAPI + SQLAlchemy（async）+ Alembic
    └── prompts/  # 资料梳理、对话编辑、样式生成的提示词
```

**后端**

```bash
cd app/backend
pip install -r requirements.txt
alembic upgrade head          # 创建数据表
uvicorn main:app --host 0.0.0.0 --port 8000
```

需要以下环境变量：

| 变量 | 说明 |
|------|------|
| `DATABASE_URL` | PostgreSQL 连接串 |
| `JWT_SECRET_KEY` | 登录令牌签名密钥，也用于加密用户的模型 Token（修改后，已保存的 Token 会失效，需要重新填写） |
| `OIDC_ISSUER_URL` / `OIDC_CLIENT_ID` / `OIDC_CLIENT_SECRET` | 登录服务（OIDC）配置 |
| `OSS_SERVICE_URL` / `OSS_API_KEY` | 头像使用的对象存储服务，需提前创建私有桶 `folio-avatars` |

**前端**

```bash
cd app/frontend
pnpm install
pnpm run build                # 产物在 dist/
```

把 `dist/` 部署到任意静态托管服务，并将 `/api` 反向代理到后端。所有前端路由（如 `/app/:id`、`/page/:slug`）都需要回退到 `index.html`。

> 注意：项目的登录和对象存储对接的是 Atoms Cloud 提供的服务。脱离 Atoms 自行部署时，需要准备兼容的 OIDC 登录服务和对象存储服务，或者改写 `backend/routers/auth.py` 与 `backend/services/storage.py` 中的对接逻辑。

### 上传到 GitHub
在 Atoms 页面右上角点击 Share，选择「Export」下载代码，在本地解压后执行：

```bash
git init && git add . && git commit -m "Folio"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

请不要把任何密钥写入代码或提交到仓库。
